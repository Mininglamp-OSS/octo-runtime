# 目标与收益

初始基线 main@ed7a4c899e56；分支 codex/255-rest-task-delivery。2026-10-30 按用户要求 rebase 到最新 origin/main@332413ae，保留全部未提交试验改动。用户授权新 worktree、OctoSpec 规划、可执行性至少 95 分后试做。未授权提交、推送、PR、安装、重启现有服务或更改系统网络。

用户确认来回切网只影响 WS，HTTP 正常；WS 实际约 20 秒后才恢复，且不保证恢复。本项按这一前提，让已经受理的工作不再等待 WS：排队仍按原顺序前进、Context 和图片可通过 HTTP 准备、进度卡与最终文本/文件通过 REST 发出。减少的时延是原来额外等待 WS 的部分，不把 20 秒当作固定 SLA。HTTP 未知结果仅保留为通用发送异常边界，不是本需求的前提，也不增加恢复前探测或等待。

决定权归 ChannelGateway：明确发送者、目标 Bot/API/空间/频道，按既有配置准备 Context 和执行环境，管理受理、队列和投递。通用 Kernel/AgentExecutor、Provider 和其他 Extra 的协议及业务策略不变；CLI 与 SDK 共用此实现。

ChannelGateway 不承担整个系统的完整可用性兜底。服务端离线重投、网络恢复、Provider 恢复和跨进程持久保障归各自责任模块；本项修复自身生命周期耦合，不新增旁路补偿其他模块。

用户后续明确旧 WS 业务发送已不用，要求直接删除混杂的耦合、检测及接管代码，不考虑这些旧 API 的兼容性。清理范围包括 WuKong 文本/文件发送、发送重试/迟到确认、未知通知，以及 REST 对当前 WS 的身份/状态查询；保留入站协议、PING/PONG 和重连，取消/身份/队列等业务保护由各自所有者承担。[设计](design.md#原有耦合与本次删除)逐项说明原逻辑与当前归属。用户授权在 #255 评论说明业务链路及删除原因，GitHub 评论使用英文；没有授权提交、推送、安装或部署。

## 关键合同

- WS 负责入站消息和控制事件、传输 ACK、检测与重连。用户后续确认心跳由 5 秒调整为每 10 秒 PING、再等一个 10 秒周期的 PONG，正常调度下静默失联约 10–20 秒发现；只影响接收连接恢复，不作为整体上线时限。任务入队后由 Bot/任务 signal 管理，不再引用接收 WS 的取消 signal 或 closed 状态。旧 WS 迟到消息仍不受理。
- 现有队列上限、FIFO、消息去重和容量拒绝不变。接收 ACK 不代表已受理或执行成功。用户明确断线期间未收到的新消息不在本项范围，不补收、不新增任务轮询或第二接收通道，不调整服务端 ACK/补投；跨进程持久恢复仍属 #78。
- 最终文本、普通控制/失败回复和原生文件消息统一调用 REST，稳定 client_msg_no、mention 和文件元数据保持。任务结果仍从执行器交给 Gateway，不经 WS 额外转发正文。
- 使用 Bot 已持有的凭据；不刷新 token、不读外部配置。Context/图片准备开始时取得同身份当前持有凭据的快照，执行工具环境保留原任务已授权身份；REST 出站每次 HTTP 尝试按既有请求授权读取生效凭据。
- 同 Bot/API/空间切网或换 token 不撤销任务；stop/reset、目标身份撤销、Bot stop 仍取消对应阶段。已明确撤销的身份再次切回不能复活旧任务。
- 传输连接代次和授权身份代次不同：A→B→A 可以创建三个 WS，但同身份保留队列、卡片消息 ID、序号、执行和投递记录。账号/空间变更则撤销旧代次。
- HTTP 有限超时、已确认不重复发、不重新 invoke。同一次在途 effect 共用 Promise；仅当前 finalMsg 和卡片 finish 首发后最多重试 3 次，使用同一消息身份或原卡 ID/序号。无回执不记为成功；耗尽后记录日志并结束，不等待 WS 补投、不再发兜底通知、不强制持久化结果。
- REST 返回有效 message_seq 时写入 Bot 层既有历史观察回调，即使 WS 离线；没有有效位置时不编造游标/覆盖关系，后续历史保守保留。旧 WS 入站位置仍按当前连接过滤。
- 普通过程卡每次快照失败即结束，不重试；后续新累计快照仍可更新。仅 finalMsg 和卡片 finish 使用上述收尾重试预算，失败必须能在 `octo-runtime channel-gateway logs` 中查询错误码与 run_id。交互按钮仍属原连接，重连后使用原有文字命令兜底，不扩展按钮迁移。

## 验收

本项受[架构接收与投递边界](../../rules/architecture.md#channelgateway-任务接收与投递边界)约束：仅沿既有接入完成 WS 下发 → Gateway 准入/排队 → buildContext/执行环境 → AgentRun → REST 卡片/finalMsg。不增加宿主或 SDK 接入步骤；既有卡片动作轮询不扩展为任务补收。

见 [设计与评估](design.md)。先用明确禁止 WS 发送并长期阻止重连的 fixture 对照旧代码，再验证来回切换、排队/准备/执行/投递各阶段，以及取消、身份、mention、附件和历史。专项仅显式本地运行，不扩大 GitHub CI 范围。真实测试仅连接 im-test；缺少账号或系统切网条件时如实标 not run，受控断开真实 WS 不表述为实际 Wi-Fi 切换。
