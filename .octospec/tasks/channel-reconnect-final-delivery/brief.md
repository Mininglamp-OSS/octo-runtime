# 长任务跨连接恢复后的最终回复

用户复现：任务执行 sleep 30 秒期间切换 Wi-Fi，WS 已恢复，但任务完成后报 OH-RUN-2005。接收消息的 reply/replyFinal 闭包固定旧连接及其 abort signal；正常网络重连也会使旧任务未发送的结果被拒绝。责任在 Gateway 的投递连接选择，不改变 Kernel/Provider 或服务端路由。

最终回复保留原 Bot、API、空间、凭据及收件地址，只允许同一 Runtime 生命周期且已经完成身份核验的当前连接承接未开始的发送。当前连接未就绪时最多等待 15 秒，并受原任务投递取消信号和 Bot 停止约束；凭据、身份或空间变更拒绝转投。上传与文件准备跟随投递期限，未发送文本/文件每次开始前选择当前连接。已经发送但确认未知的操作不跨连接重放；不重新 invoke，不改旧任务执行结果，不新增持久投递库。

保留现有进度卡和交互连接生命周期，不迁移旧交互按钮；本次修复最终文本/文件及普通回复。测试覆盖长任务先重连后完成、恢复间隙等待、身份与凭据不串用、停止取消等待、已发送未知不重放。专项本地验证，不扩大 CI；不提交 Git。

后续 REST 进度卡生命周期由 channel-rest-card-lifetime 任务补齐。双轴审查要求空回复、失败、取消等普通终态提示同样携带该轮投递 signal/obsolete；不准备产物或 mention 的分支不能丢失取消权。真实 Runtime 回归覆盖空终态在等待重连时收到 /stop 和 /reset 后不再发出旧提示。

PR #251 审查补充：送达结果未知的独立 REST 通知也属于原任务出站行为，必须复用进度卡的身份检查，在能力查询和实际 POST 前分别核验 Bot 生命周期及当前已确认的 Bot/API/空间/凭据；身份变化拒绝请求，不能用旧凭据继续发提示。正常同身份离线不以 WS online 作为 REST 准入条件，未知原消息仍不重放。
