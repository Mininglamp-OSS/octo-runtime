# Issue 101 实施验证

需求、完整英文提示与边界见[任务简报](../../tasks/101-bot-mention/brief.md)。基线为最新远端 `main@102fb9c`，分支为 `research/issue-101-mention`。

## 行为与边界

- Gateway 在请求装配时将默认英文 mention 控制指令追加在宿主本轮有效 `entries` 后，构造唯一 `octo.control/instructions` item。ExtraSet 中显式配置的指令属于宿主内容，在前保留；顺序、重复内容和宿主空白均保留，不修改输入或累计旧人设。
- 静态/动态宿主人设仍按原规则替换，公共 Context 合并与 mandatory 合同保持原语义；新默认只属于 Octo Gateway，不进入 WeCom 等其他 Extra。
- 默认控制规则带 `[OCTO_CHANNEL_MENTION_RULES_V1]` 边界，整段及每轮普通 Context 短提醒均为英文。逐轮提醒覆盖已有 Provider binding，不自动 reset。
- 用户授权的交接可将明确 `robot=1/true` 的当前 Bot 成员转换为原生 mention；真人继续接受 `robot=0/false`。保留 Markdown 结构排除、广播 UID 拒绝、成员核验和查询失败时的纯文本降级。
- 发送沿原连接携带可读正文及准确 UTF-16 entities；不增加 CLI 发送或模型重跑。接收 Bot 仍须明确允许发送 Bot 并通过原有准入。
- 自消息拒绝位于命令、Context 准备和 AgentRun 调度前。自己 @ 自己、AI 广播或自己列入 allowed_sender_ids 都不能绕过，覆盖私聊、群和话题。该行为原本已有，本轮补充明确注释、针对性回归和 Octospec 强制约束。
- 默认控制指令计入原 32 项 / 64 KiB 预算，不静默丢弃控制指令或显式业务项。两个既有项数预算 fixture 调整一项，为新增必需控制 item 留出位置，仍验证原有自动历史降级。
- 按用户明确要求，compaction 保留交给模型遵守英文提示，不新增保留机制、不触发或验证模型 compaction。
